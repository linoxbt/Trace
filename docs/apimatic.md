# PayPal Server SDK, written with APIMatic's Context Plugin

Trace's order and payment calls go through PayPal's own TypeScript Server SDK
([`@paypal/paypal-server-sdk`](https://www.npmjs.com/package/@paypal/paypal-server-sdk)
2.5.0, generated by APIMatic). The integration was written from APIMatic's
**PayPal Server SDK Context Plugin**
([`paypaldev/server-sdk-context-plugin-preview`](https://github.com/paypaldev/server-sdk-context-plugin-preview)),
whose TypeScript skills ground every SDK fact in the SDK's own source rather
than in what a model remembers about PayPal.

## What runs on the SDK

`packages/paypal/src/sdk.ts`, `PayPalSdkClient`:

| Trace call | SDK operation |
| --- | --- |
| Create the order (intent `AUTHORIZE`, items, payee, brand) | `OrdersController.createOrder` |
| Read an order | `OrdersController.getOrder` |
| Authorize the approved order | `OrdersController.authorizeOrder` |
| Read a hold | `PaymentsController.getAuthorizedPayment` |
| Capture part of a hold, or the last part | `PaymentsController.captureAuthorizedPayment` |
| Renew a hold after the honor period | `PaymentsController.reauthorizePayment` |
| Release what's left of a hold | `PaymentsController.voidPayment` |
| Read a capture | `PaymentsController.getCapturedPayment` |
| Refund, acting for the tradesperson's account | `PaymentsController.refundCapturedPayment` with `paypalAuthAssertion` |

It's the client the app, the scheduled worker and the sandbox script use
(`createPayPalClient`). Setting `PAYPAL_HTTP=fetch` switches back to the
hand-written client, which the SDK client extends and which still covers what
the SDK doesn't: disputes, partner onboarding (Partner Referrals and
merchant-integrations) and webhook signature checks.

## What the plugin's skills changed

- **typescript-getting-started**: pin the exact version (`2.5.0`, no caret),
  construct controllers with `new OrdersController(client)`, import enums as
  values (`CheckoutPaymentIntent.Authorize`,
  `PaypalWalletContextShippingPreference.NoShipping`) and models as types, and
  read signatures from the SDK's `src/` rather than guessing. Every request
  body is a typed model the SDK checks before sending.
- **typescript-error-handling**: an error's `result` is only parsed for typed
  subclasses, so Trace reads the raw `body` on every `ApiError` and turns it
  into the same `PayPalError` (status, name, issues, debug ID) the guard's
  rules already understand. A request the SDK's schema rejects before
  sending (`ArgumentsValidationError`) is a bug and is never retried; any
  other failure is a request that got no answer, so it becomes
  `PayPalNetworkError` and the capture is retried later with the same
  `PayPal-Request-Id`.
- **typescript-configuration-resilience**: read the generated
  `DEFAULT_RETRY_CONFIG` rather than assume it. Retries are off there, and
  Trace pins them off explicitly: it retries captures itself with stored
  request IDs, and an SDK retry underneath would hide an unknown outcome from
  it. The generated timeout is `0`, which means none, so Trace sets one (30 s,
  15 s in the scheduled worker).
- **typescript-testing**: the seam is a stub axios adapter passed through
  `unstable_httpClientOptions`. `packages/paypal/test/sdk-contract.test.ts`
  sends the SDK client and the hand-written client through the same stub
  PayPal and requires the same method, path, body, idempotency and
  auth-assertion headers, results and errors for every call above (15 tests).

One decision is Trace's own: a 2xx answer that the SDK's response schema
rejects (say, a status value newer than the SDK) throws
`ResponseValidationError`, but PayPal has already acted on it, so money may
have moved. Trace treats it as a success and reads its raw body, never as a
failure to retry.

## The one difference on the wire

The SDK sends `PayPal-Partner-Attribution-Id` only where PayPal's spec
declares it, when creating the order. The hand-written client also sent it on
captures and voids. The contract test allows exactly that difference.

## Installing the plugin

```
npx context-plugins install https://github.com/paypaldev/server-sdk-context-plugin-preview
```

The skills then load in Claude Code for questions about the SDK. The cloud
session that wrote this integration couldn't run the installer, so it read the
same skill files straight from the plugin's repository.
